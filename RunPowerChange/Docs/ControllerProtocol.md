# 달려라! 전력 챌린지 - 쳇바퀴 센서 통신 규약 (임시안 v0.3)

PC(Unity 1대) ↔ 쳇바퀴 회전 센서 컨트롤러. 센서는 **쳇바퀴가 1회전할 때마다 신호 1개**를 보낸다.
장치 사양이 정해지면 이 문서와 `WheelSensorLink`를 함께 고친다.

## 1. 연결

| 항목 | 값 |
|---|---|
| 방식 | RS232 (USB-Serial 가능). **쳇바퀴 1대당 컨트롤러 1대, 포트 1개** |
| 속도 | 19200 bps, 8N1, 흐름 제어 없음 |
| 포트 | `persistentDataPath/port.json`의 `controllerId`별 COM (디버그 패널 드롭다운에서 바꿀 수 있음) |
| 쳇바퀴 연결 | `Setting.json`의 `wheels[].controllerId` — 기본 컨트롤러 1 → 쳇바퀴 1, 컨트롤러 2 → 쳇바퀴 2 |
| 문자 | ASCII, 대문자 |
| 줄 끝 | 컨트롤러 → PC: `\n` 또는 `\r\n` / PC → 컨트롤러: `\n` |

## 2. 컨트롤러 → PC

| 메시지 | 시점 | 의미 |
|---|---|---|
| `R1` | 쳇바퀴가 1회전할 때마다 | 1회전 1번. 어느 쳇바퀴인지는 신호가 들어온 포트(컨트롤러 id)로 정한다 |
| `PONG` | `PING` 응답 | 연결 확인 |
| `ERR,내용` | 수시 | 장치 오류 (PC는 로그만 남김) |

- 두 컨트롤러는 같은 펌웨어(같은 `R1` 신호)를 써도 된다. 쳇바퀴마다 다른 체험자가 달리므로 PC가 포트로 구분한다.
- 멈춰 있을 때는 아무것도 보내지 않아도 된다.
- 센서 채터링(한 번 지날 때 신호가 여러 번)은 장치에서 거르는 것을 권장하지만, PC도 `maxValidSpeedKmh`보다 빠른 간격은 버린다.

## 3. PC → 컨트롤러

| 명령 | 시점 | 컨트롤러 동작 |
|---|---|---|
| `PING` | 5초마다, 열린 모든 포트로 | `PONG` 응답 (응답 없어도 PC는 계속 동작, 연결 상태 표시용) |

## 4. PC 처리

| 상황 | 처리 |
|---|---|
| 회전 신호 | 거리 += `wheelCircumferenceM` (기본 6.283m = 직경 2m) |
| 속도 | 둘레 ÷ 직전 회전과의 간격. 다음 회전이 늦어지면 둘레 ÷ 경과시간으로 줄어든다 |
| 정지 후 첫 회전 | 간격을 알 수 없으므로 거리만 더하고 속도는 다음 회전부터 |
| `rotationStopSeconds`(기본 5초) 동안 신호 없음 | 속도 0 |
| 간격이 `maxValidSpeedKmh`(기본 40km/h) 초과로 환산 | 센서 튐으로 보고 무시, 경고 로그 |
| 화면 거리 | 회전마다 6m씩 뛰지 않게 속도로 보간. 확인된 회전 수를 넘지 않고 1회전 넘게 뒤처지지 않는다 |
| 쳇바퀴가 연결되지 않은 컨트롤러 / 알 수 없는 메시지 | 디버그 패널에 "무시됨(이유)" 기록 |
| 포트 닫힘 / 장치 없음 | 시뮬레이션 키(`wheels[].simulateKey`, 기본 ↑ / W)를 누를 때마다 회전 신호 1개를 만들어 같은 경로로 처리 (누른 간격으로 속도 계산) |

모든 수신과 해석 결과(회전 인식·간격·속도 / 무시됨과 이유)는 `SerialPortLogPanel`에 남긴다.

## 5. 장치 쪽 확인 필요

- 센서 종류(근접/홀/리드)와 쳇바퀴 1회전당 신호가 정확히 1번인지 (자석 여러 개면 `wheelCircumferenceM`을 나눠서 맞춤)
- 쳇바퀴 실제 둘레 (달리는 면 기준)
- 마그네틱 브레이크·벽면조명을 PC가 제어해야 하는지 (현재 규약에는 없음)
