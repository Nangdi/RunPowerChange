# 달려라! 전력 챌린지 - 쳇바퀴 센서 통신 규약 (임시안 v0.1)

PC(Unity 1대) ↔ 쳇바퀴 RPM 센서 컨트롤러. 장치 사양이 정해지면 이 문서와 `WheelSensorLink`를 함께 고친다.

## 1. 연결

| 항목 | 값 |
|---|---|
| 방식 | RS232 (USB-Serial 가능), 쳇바퀴 1대당 포트 1개 |
| 속도 | 19200 bps, 8N1, 흐름 제어 없음 |
| 포트 | `persistentDataPath/port.json` — `controllerId`가 `Setting.json`의 `wheels[].controllerId`와 같은 항목, `enabled: true` |
| 문자 | ASCII, 대문자 |
| 줄 끝 | 컨트롤러 → PC: `\n` 또는 `\r\n` / PC → 컨트롤러: `\n` |
| 구분자 | `,` (공백 없음) |

## 2. 컨트롤러 → PC

| 메시지 | 주기 | 의미 |
|---|---|---|
| `P,n` | 100ms 권장 (멈춰 있어도 송신) | 전원 투입 후 **누적 펄스 수** `n` (0 ~ 4294967295, 넘치면 0부터). PC는 직전 값과의 차이로 거리·속도를 계산 |
| `RPM,n` | 100~200ms | `P`를 보낼 수 없는 장치용. 롤러 분당 회전수(정수 또는 소수). PC가 시간 적분으로 거리를 계산 |
| `ERR,내용` | 수시 | 장치 오류 (PC는 로그만 남김) |

- `P`와 `RPM` 중 하나만 보내면 된다. 거리 정확도 때문에 `P`를 권장한다.
- 펄스 수/회전당 펄스와 롤러 둘레는 `Setting.json`의 `pulsesPerRevolution`, `rollerCircumferenceM`.

## 3. PC → 컨트롤러

| 명령 | 시점 | 컨트롤러 동작 |
|---|---|---|
| `PING` | 5초마다 | `PONG` 응답 (응답 없어도 PC는 계속 동작, 연결 상태 표시용) |

## 4. PC 처리

| 상황 | 처리 |
|---|---|
| `P,n`이 직전 값보다 작음 | 컨트롤러 재시작 또는 넘침으로 보고 기준값만 다시 잡음 (거리 증가 0) |
| 한 번에 비정상적으로 큰 증가 (속도 40km/h 초과 환산) | 무시하고 기준값만 갱신, 경고 로그 |
| `sensorStopSeconds` 동안 값 변화 없음 | 속도 0 |
| 포트 닫힘 / 장치 없음 | 시뮬레이션 키 입력으로만 동작, 체험 흐름은 멈추지 않음 |
| 알 수 없는 메시지 | 디버그 패널에 "무시됨(형식 오류)" 기록 |

모든 수신과 해석 결과(인식됨/무시됨과 이유)는 `SerialPortLogPanel`에 남긴다.

## 5. 장치 쪽 확인 필요

- 센서 종류(근접/홀/엔코더)와 1회전당 펄스 수
- 센서가 붙는 롤러의 둘레 (또는 쳇바퀴 2m 직경과의 회전비)
- 컨트롤러 1대가 쳇바퀴 2대를 같이 받는지 → 그렇다면 `P1,n` / `P2,n`처럼 쳇바퀴 번호를 붙이는 방식으로 바꿈
- 마그네틱 브레이크·벽면조명을 PC가 제어해야 하는지 (현재 규약에는 없음)
